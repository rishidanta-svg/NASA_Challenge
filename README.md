# Littoral — which coastline does each satellite see?

**NASA Space Apps Challenge 2026 · Challenge #5 "Dancing with the SARs" · Duck, North Carolina (USACE Field Research Facility)**

When satellites disagree about a changing coastline, which physical feature does each one actually detect, what really changed on the beach, and how confident should we be?

We compare NASA–ISRO **NISAR** (L-band radar), **Sentinel-1** (C-band radar) and **Sentinel-2** (optical) against hourly **tower lidar** at Duck, NC, for June, September and October 2026. Lidar measures the beach; each satellite's boundary is scored against the lidar line it physically corresponds to: the dune toe, the wet/dry edge or a fixed contour. The lines are never merged into one "coastline".

This is a single-site case study and an independent project, not an official NASA, ISRO or USACE product.

## Results

All results, with accuracy, 95% intervals and an evidence tag (SUPPORTED / PLAUSIBLE / NOT DEMONSTRATED) assigned by written rules, are in:

- **[`VALIDATION_SUMMARY.md`](VALIDATION_SUMMARY.md)**: plain-English report, generated by code from `outputs/`
- **The app, [`dist/index.html`](dist/index.html)**: the same numbers, interactive
- **Independent test**: every method is also tested with whole dates and stretches of beach held out, against simple baselines ("typical position", "no change"); see the summary's "Independent test" section
- **[`outputs/figures/`](outputs/figures/)**: presentation graphs (PNG and interactive HTML)
- **[`CITATIONS.md`](CITATIONS.md)**: every dataset with product or granule ID, UTC time, URL and access date

No number in the report or the app is typed by hand: they are written by `src/make_report.py` and `src/export_app_data.py` from the pipeline's CSVs, and `src/selfcheck.py` verifies that.

## The app

Open `dist/index.html` directly in a browser (no server or build step needed), or serve it:

```bash
python -m http.server 8000 --directory dist
```

- **Explore**: map of lidar elevation change (June → October) with every sensor's edge on all 50 rows of beach; click a row to see its cross-section with the lowered area shaded.
- **Sensors & trust**: what each sensor actually sees, how accurately, and every claim with its evidence level.
- **Timeline**: when each image was taken (UTC) and the water level at that moment.
- **Sources & limits**: products used, coordinate definitions and "where this could be wrong".

## Reproduce

Requires Python 3.13.

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
```

Rebuild everything from the included preprocessed data (no account needed):

```bash
.venv/bin/python run_validation.py --skip-download
```

Re-download everything from the original sources:

```bash
.venv/bin/python src/earthdata_login.py
```

```bash
.venv/bin/python run_validation.py
```

- `earthdata_login.py` asks for your free [NASA Earthdata](https://urs.earthdata.nasa.gov) username and password once and saves them to `~/.netrc`; it is only needed for NISAR. Lidar (FRF THREDDS), tides (NOAA), Sentinel-2 (Earth Search on AWS) and Sentinel-1 RTC (Microsoft Planetary Computer) need no login.
- NISAR files are about 5 GB each; the pipeline reads only the ~21 MB beach window over HTTPS range requests.
- The run ends with `selfcheck.py`; results are in `outputs/self_checks.csv` and at the end of the summary.

## Layout

| Path | What it is |
|---|---|
| `run_validation.py` | One command that runs every step in order |
| `src/` | Fetching, boundary extraction, scoring, figures, report, app data, self-checks |
| `data/processed/` | Small preprocessed inputs (lidar scans, satellite profiles, tide) |
| `outputs/` | Result tables (CSV) and figures |
| `dist/` | The web app; `dist/data.js` is generated, do not edit |
| `CLAUDE.md` | Project rules for AI coding assistants used by the team |
| `REVIEW_OF_GEMINI_VERSION.md` | What was wrong in the previous package and how it was fixed |
| `AUDIT_RESPONSE.md` | Which points of the physics-model audit apply here, and what was done |
| `src/improvements.py` | Independent test (held-out dates and places), simple baselines, wave-runup physics, calibrated NISAR combination, location sensitivity |
| `src/fetch_calibration.py` | Wave data (FRF 17 m Waverider) and separate calibration lidar scans used only for beach slope |
